# screeps-ps

PureScript bindings for the Screeps game API. Most bindings are generated by a pipeline: the official docs are split into per-member specs, and small-model workers write one module per task. Older PureScript Screeps bindings exist but are long abandoned; don't take conventions from them.

## Layout

| Path | What it is | Edit it? |
|---|---|---|
| `src/Screeps/Types.purs`, `Constants.purs` (+ `.js`) | every game-object type, inheritance class and constant | No: generated by `tools/gen-shared.py` |
| `shared-index.md` | short summary of Types/Constants, pasted into the worker agent | No: generated with them |
| `src/Screeps/Memory.purs`, `src/Screeps/Game/GetObjectById.purs` | hand-written modules | Yes |
| `src/Screeps/Internal/<Object>/PartN.purs` (+ `.js`) | worker output, one pair per task | Small hand fixes only (see below) |
| `src/Screeps/<Object>.purs` | facades re-exporting an object's parts | No: generated by `split_specs.py facades`, starts with `-- Generated by split_specs.py facades` |
| `split_specs/<Object>/NN-<member>.md` | one processed doc entry per member | Yes, to correct a doc entry before re-running its task |
| `tasks/` | worker task specs + `manifest.tsv` | No: generated by `split_specs.py plan` |
| `tools/handwritten.txt` | members excluded from generation (`Title:member` per line) | Yes |
| `.claude/agents/binding-writer.md` | the worker's instructions: ALL binding conventions | Yes; see "Changing conventions" |
| `run_bindings.sh` | runs one worker per manifest row, commits each success | Yes |
| `tools/verify_bindings.py` | static checks over generated modules | Yes; keep in sync with the agent file |
| `test/` | smoke tests with game globals stubbed | Yes |

## Binding conventions

`.claude/agents/binding-writer.md` is the single source of truth for naming, overload splitting, types, Effect vs pure, and FFI style. Follow it for hand-written bindings too, and read it before reviewing worker output. The rules most often gotten wrong:

- Never declare game-object types outside `Screeps.Types` (PureScript forbids cyclic imports).
- Every foreign import with 2+ args is uncurried (`FnN` / `EffectFnN`). Every effectful import with 1+ args uses `EffectFnN`, never `a -> Effect b`.
- Never export `<name>Impl` foreign imports; export only the wrappers.
- JS is plain ES2017: no `?.` or `??`. Read `Game`, `Memory` etc. only inside function bodies; they're replaced every tick. (`Constants.js` reads constants at load time on purpose: they never change.)

## Commands

Run everything from the repo root.

```bash
npm install                      # dev-only: @screeps/common's constants table
spago build
test/run.sh                      # build + smoke tests with stubbed globals

# regenerate shared modules (needs a screeps/docs checkout outside the repo)
python3 tools/gen-shared.py . <docs>/api/source
# then re-paste shared-index.md into .claude/agents/binding-writer.md

# generation pipeline
python3 tools/split_specs.py split <docs>/api/source split_specs
python3 tools/split_specs.py plan split_specs tasks --max-members 3 --skip tools/handwritten.txt
./run_bindings.sh [tasks/manifest.tsv]

# after a run
python3 tools/split_specs.py facades tasks/manifest.tsv
spago build
python3 tools/verify_bindings.py --skip tools/handwritten.txt
```

## Workflow rules

- `run_bindings.sh` needs a clean tree: it stops if anything is uncommitted, and after each task if anything other than that task's two files changed. It deletes untracked facades on start. Commit hand fixes before running it.
- Don't re-run `plan` once tasks have run: it renumbers parts, so finished modules no longer match their task keys. Re-plan only when starting over.
- To re-run a finished task: remove its `.done/<key>` marker, `git rm` its two files, commit, then run the loop. Unfinished tasks (no `.done` marker) are retried automatically.
- Commit facades only once all reruns are done and the full build is clean. A committed facade importing a removed part breaks every worker's build.
- Hand fixes to a part module must touch every place a binding lives: export list, foreign import / wrapper and its comments, the JS export, and any imports that become unused.
- Members bound by hand or deliberately omitted go in `tools/handwritten.txt`, so `plan` and the verifier both skip them.

## Changing conventions

When a rule in `binding-writer.md` changes:

1. Update `tools/verify_bindings.py` if the rule affects names, arity or types (its naming logic mirrors the agent file).
2. Re-run the affected tasks rather than hand-patching many modules, so the generator and its output stay consistent.
3. Keep the agent file short: workers re-send it on every turn.

## Safety

- Workers run with `--permission-mode dontAsk` and may only edit their own two files and run `spago build`. Don't widen that, and never use `--dangerously-skip-permissions` or `bypassPermissions`.
- `@screeps/common` (dev-only) pulls in an old lodash flagged by `npm audit`. lodash is never loaded by the file we use; don't run `npm audit fix --force`, which would swap the constants table.
